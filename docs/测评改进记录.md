## 一、图片 WebP

**做法**

- `tools/img_webp.js` 用 Chromium Canvas 从现有 JPEG 生成两档 WebP（1080w q=0.80 / 480w q=0.78），原 JPEG 保留作回退；
- `util.webpSource()` 输出 `<source type="image/webp">`，列表、详情画廊、抽店结果、打卡、游玩点位共 5 处接入 `<picture>`；
- `picture { display: contents }`，图片容器布局完全不变；
- 顺带修正 srcset：改用 `1x / 2x` 密度描述符。部分素材原图不足 480px，写死 `480w` 会让浏览器误判清晰度。

**数据**

| 资源 | JPEG | WebP | 变化 |
|---|---|---|---|
| 缩略图（8 张，覆盖 16 家店） | 246.6 KB | **167.0 KB** | -32% |
| 大图（8 张） | 1202.2 KB | **780.1 KB** | -35% |

不支持 WebP 的旧浏览器自动回退 JPEG，不会白屏。

## 二、前端错误上报

**端点**：`POST /api/client-error`

```json
{ "kind": "error", "message": "boom", "source": "app.js", "line": 12,
  "stack": "Error: boom...", "path": "/" }
```

- 只接受 JSON，字段超长自动截断；空 message 返回 400；
- 写入服务端日志（含 `X-Request-Id`），不采集用户标识、不记录 query；
- 换行会被替换为空格，避免日志注入。

**客户端**（`static/js/telemetry.js`，打包时最先加载）：

- 捕获 `window.onerror`、`unhandledrejection`、图片加载失败；
- 同一条错误只报一次，单页最多 6 条，避免错误风暴；
- 优先 `sendBeacon`，失败降级 `fetch keepalive`；
- `api.js` 对 `network / timeout / server_error / bad_response` 额外上报一次，且排除上报接口本身，避免递归。

**测试**：后端 5 项（成功、缺字段、非 JSON、超长、GET 405）；E2E 触发一次错误事件并断言上报计数增加。

## 三、Nginx 生产配置

`deploy/nginx.conf` 提供可直接改域名使用的配置：

- 80 → 443 跳转、TLS 1.2/1.3、HTTP/2；
- `/assets/` 一年 immutable，`/static/` 一周缓存；
- gzip 兜底（应用已压缩时不会重复压），brotli 配置以注释给出；
- `X-Forwarded-For / Proto` 透传，配合应用侧 `TRUST_PROXY=1`、`SESSION_COOKIE_SECURE=1`。

## 五、压测中发现并修复的两个缺陷

### 1. 并发下 SQLite 偶发 `readonly database`

**现象**：用 12 个并发线程同时请求 `/api/auth/device` 和 `/api/restaurants`，40 次里有 1 次 500：

```
sqlite3.OperationalError: attempt to write a readonly database
```

**原因**：每个请求都新建连接并执行 `PRAGMA journal_mode = WAL`。WAL 是持久化属性，重复设置会在并发打开时抢排他锁；同时最后一个连接关闭会删除 `-wal/-shm`，与正在打开的新连接竞争，Windows 上表现为 SQLITE_READONLY。

**修复**（`services/db.py`）：

1. `journal_mode` / `synchronous` 只在 `init_db` 设置一次，每请求连接只设 `foreign_keys` 与 `busy_timeout`；
2. 启动时保留一个常驻连接（keeper），避免 WAL/SHM 在请求间隙被删除；
3. `busy_timeout` 5s → 8s，`connect timeout` 10s → 15s。

**复测**：16 并发 × 60 次，`/api/auth/device` 60/60 返回 200，`/api/restaurants` 60/60 返回 200。

### 2. 默认限流对共享出口 IP 偏低

**现象**：压测与 E2E 连续运行后，同一 IP 出现 429；办公网 / 校园网多设备共用一个出口 IP 时，120 次/分会误伤正常用户。

**处理**：默认 `RATE_LIMIT_PER_MINUTE` 120 → **300**；配置真实地图 Key 后，搜索接口仍单独按 40 次/分收紧，保护付费上游配额。E2E 与 bench 连续运行不再互相干扰。

## 六、取舍与残留

- **不上 AVIF**：编码更慢、旧设备解码兼容性差，当前 WebP 已覆盖 97%+ 浏览器；后续可按需增加。
- **不上传完整堆栈**：只保留 1200 字符，避免日志膨胀与潜在隐私内容。
- **错误上报不做聚合看板**：当前写入日志，规模化后接入 Sentry/自建聚合即可，端点无需改动。
- **SQLite 未替换**：单机 2 worker 足够；换库涉及迁移与运维，留到有并发写入压力时再做。
