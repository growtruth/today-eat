# 数据采集说明（来源 / 范围 / 方式 / 解析 / 频率 / 校验）

本文对应代码：`services/crawler.py`、`services/provider_amap.py`、`services/provider_baidu.py`、`services/provider_osm.py`、`services/data_service.py`。

> 一句话：本项目只采集**地图开放平台的公开 POI 数据**与 **OpenStreetMap 开放数据**；不采集小红书、美团、大众点评、抖音的单条内容。原因与替代方案见第六节。

---

## 一、来源与范围

| 来源 | 接口 | 采集范围 | 主要字段 | 许可 / 前提 | 频率 |
|---|---|---|---|---|---|
| 高德地图 Web 服务 | `GET /v3/place/around`、`/v3/place/detail`、`/v3/direction/*`、`/v4/direction/bicycling`、`/v3/geocode/geo` | 以用户坐标为圆心、半径 ≤8km 的餐饮 POI（类型码 `050000`），最多 2 页 × 25 条 | 名称、地址、坐标、类型、评分、人均、营业时间、公开图片 URL、距离 | 高德开放平台服务条款，需申请 **Web 服务 Key** | 1 秒/次 |
| 百度地图 Place API | `GET /place/v2/search`、`/place/v2/detail`、`/geocoding/v3`、`/directionlite/v1/*` | 同上，半径 ≤8km；坐标 BD-09，服务端统一转 GCJ-02 | 名称、地址、坐标、类型、标签、人均、评分、营业时间 | 百度地图开放平台条款，需 **服务端 AK** | 1 秒/次 |
| OpenStreetMap | `POST overpass-api.de/api/interpreter`（含 2 个备用镜像） | 半径 ≤8km 的 `amenity=restaurant/cafe/fast_food/bar/pub` 节点与建筑 | 名称、菜系、地址、营业时间、电话、官网、坐标 | **ODbL 1.0**，需署名 OpenStreetMap contributors | 3 秒/次 |
| 项目演示数据 | `data/*.json` | 16 家望京示例门店 + 8 个游玩点位 | 全字段 | 项目自建；图片来自需求包实拍素材 | 无外部请求 |

**采集边界**：

- 只取公开 POI 的展示型字段，不采集用户身份、手机号、订单、支付信息；
- 图片只使用接口返回的公开图片 URL，**不绕过防盗链、不下载后二次分发**；
- 不做全站遍历、不做增量爬库、不做账号态请求。

## 二、采集方式

```
浏览器定位 / 手动商圈
        │
        ▼
DataService.search(lat, lng, radius)
        │  半径阶梯 3km → 5km → 8km
        ▼
逐源调用 provider.search_nearby()
        │  crawler.fetch_json()：按 host 限流 → 请求 → 解析
        ▼
校验 → 去重 → 按距离排序 → 返回前端
```

### 请求节流

`HostLimiter` 以 host 为粒度维护最小间隔，单进程内串行：

- 高德 / 百度：`min_interval = 1.0s`
- OSM Overpass：`min_interval = 3.0s`（遵守公共实例使用政策）
- 参数可在 `services/crawler.py:SOURCES` 调整，`REQUEST_INTERVAL` 控制全局下限

### 重试与退避

`fetch_json()` 对**网络异常、超时、429、5xx** 重试，最多 2 次：

| 次数 | 退避 |
|---|---|
| 第 1 次失败 | 0.6s |
| 第 2 次失败 | 1.2s |
| 第 3 次失败 | 2.4s（随后抛错） |

4xx（除 429）视为不可重试，直接切换下一个数据源。单次请求超时 6 秒（OSM 8 秒）。

### 多源容错链

1. 同一半径下按 `amap → baidu → demo` 顺序尝试（可配置）；
2. 当前源失败或结果 < 3 条 → 换下一个源 / 扩大半径；
3. 半径用尽仍无结果 → `FriendlyError("附近暂时没找到合适的店", hint="点我重试，或手动输入城市+商圈")`；
4. 任何堆栈、URL、状态码只写服务端日志，**不返回前端**。

## 三、解析逻辑

### 高德

```python
location = poi["location"]                    # "lng,lat" → float
rating   = float(biz_ext["rating"])            # 缺省 None
cost     = float(biz_ext["cost"])              # 缺省 None
hours    = biz_ext["opentime2"] or "open_time" # "10:00-22:00"
images   = [p["url"] for p in poi["photos"][:6]]
cuisine  = classify(poi["type"] + poi["name"]) # 关键词规则表
distance = haversine(user, poi)                # 本地复算，不信任接口 distance
```

- 菜系映射：`火锅/涮肉`、`日本料理/寿司/居酒屋`、`烧烤/烤串/烤肉`、`甜品/蛋糕`、`咖啡`、`奶茶/茶饮`、`小吃/面馆/卤煮`、`川菜/四川`、`西餐/牛排/酒吧`，未命中归「中餐」；
- 标签推导（**启发式，非平台原字段**）：
  - 人均 ≥ 100 → `周末友好`；≥ 150 → `有包间`；
  - 评分 ≥ 4.5 且图片 ≥ 3 张 → `适合拍照`；
  - `isNew` 不伪造（平台不提供该字段，真实源恒为 `false`）。

### 百度

- 接口返回 BD-09，先 `bd09_to_gcj02()` 再入库，保证与高德、浏览器定位可直接混算；
- `detail_info.price` / `overall_rating` 可能是字符串，统一转 float 后进入校验；
- 百度搜索接口不返回图片 URL，`gallery` 为空，前端按菜系使用本地占位图。

### OpenStreetMap

- `elements[*].tags` 取 `name / cuisine / addr:street / opening_hours / phone / website`；
- 无评分、人均、图片 → 对应字段为 `None`，前端显示「暂无评分 / 人均待补充」，不猜造；
- `id` 使用 `osm-{type}-{id}` 保证跨请求稳定。

### 演示数据

- 门店坐标由「中心点 + 距离 + 方位角」推算，保证列表距离与筛选档位自洽；
- 评价语料为项目自建（`data/reviews.json`），按门店 id 做稳定哈希抽取，非任何平台抓取内容。

## 四、准确性校验（`crawler.validate_item`）

| 校验项 | 规则 | 处理 |
|---|---|---|
| 名称 | 去 HTML、压缩空白、≤40 字 | 空名 / 非法名直接丢弃 |
| 坐标 | 中国境内 bbox（纬度 3~54，经度 73~136） | 越界丢弃 |
| 距离 | `haversine` 本地复算 | 与上游偏差 > max(200m, 40%) 记 `distance_mismatch`，以复算值为准 |
| 评分 | `0 < rating ≤ 5` | 越界置 `None` 并记 `rating_out_of_range` |
| 人均 | `1 ≤ price ≤ 5000` | 越界置 `None` 并记 `price_out_of_range` |
| 图片 | 仅 `http(s)` 或 `/static/`，去重，≤6 张 | 无图记 `no_photo`，前端用占位图 |
| 营业时间 | `HH:MM-HH:MM` 正则 | 不合法清空，不阻塞展示 |
| 主键 | 缺失时用 `md5(name+坐标)` 生成 | 记 `id_generated` |
| 去重 | 同 id，或同名且距离 ≤45m | 丢弃后到者 |

校验结果通过 `/api/sources` 的 `stats[].issues` 实时可见（如 `no_photo: 12`、`distance_mismatch: 1`），便于评估数据质量。

**已知偏差**：

- 高德/百度的 `rating` 为平台聚合分，与店内实际口碑存在偏差；
- `cost` 为平台人均，非实时菜单价；
- 特色街巷、顺路度为**本地几何计算**，非平台字段（见 `docs/../README.md` 规则表）。

## 五、异常处理

| 异常 | 用户可见文案 | 服务端行为 |
|---|---|---|
| Key 未配置 | 无（自动降级） | 跳过该源 |
| 网络超时 / 5xx | 「数据没拉到，可能是网络开小差了」 | 重试 2 次后切源 |
| 429 限流 | 同上 | 退避后切源 |
| 返回空结果 | 「附近暂时没找到合适的店」 | 扩半径 → 切源 |
| JSON 解析失败 | 同上 | 记 `bad json`，切源 |
| 参数非法 | 「参数格式不对」 | 400 语义，仍返回 200 + ok:false |
| 未捕获异常 | 「刚刚走神了一下，再试一次？」 | 记录完整堆栈到日志 |

前端另有兜底：详情拉取失败时用列表数据渲染，不阻断页面；图片 `onerror` 回落到菜系占位图。

## 六、合规边界与第三方平台

### 不做的事

**不采集**小红书、美团、大众点评、抖音的任何单条笔记、评价、评分、图片。原因：

1. 上述平台用户协议明确禁止未经许可的抓取、复制与再利用；
2. 用户评论可能包含个人信息，抓取与二次展示涉及《个人信息保护法》；
3. 平台内容受著作权保护，批量复制存在侵权风险；
4. 绕过登录、Cookie、签名、验证码获取数据，可能触及《反不正当竞争法》与《数据安全法》。

因此本项目**没有**实现这些平台的登录态抓取、Cookie 池、签名逆向、验证码识别等能力，也不会提供绕过鉴权的实现。

### 替代方案（已实现 / 可扩展）

| 需求 | 合规替代 | 现状 |
|---|---|---|
| 看评价 | 地图 POI 公开评价摘要 + 「去高德/百度看完整评价」跳转 | 已实现 |
| 看笔记/种草 | 跳转原平台官方页，不复制正文 | 已实现（详情页跳转） |
| 收藏某条内容 | 用户手动粘贴链接，本地只存链接与标题（不抓正文） | 可扩展，需产品确认 |
| 官方数据 | 申请各平台开放平台权限（OAuth / 应用授权）后调用官方 API | 需商务与资质 |
| 商家信息 | 地图开放平台 POI（本方案主路径） | 已实现 |

> 如果业务确实需要小红书/美团/抖音内容，正确路径是走官方开放平台或商务授权，而不是抓取。需要的话我可以按官方 API 文档接入，并把授权流程做成可配置项。

## 七、如何启用真实采集

1. 申请高德 **Web 服务 Key**（或百度服务端 AK）；
2. 写入 `.env`：`AMAP_WEB_KEY=...`；
3. 重启应用；
4. 打开首页底部「采集说明」，确认「当前使用」标记落在高德/百度；
5. 观察 `/api/sources` 的 `stats`：`requests / success / failed / items / rejected / issues`。

若只想验证无 Key 的真实公开数据，可设 `MAP_PROVIDER=osm`（字段较少，无评分/人均/图片）。
