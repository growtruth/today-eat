# 认证与鉴权审计（无认证替代方案）

审计对象：当前仓库的全部代码与运行时依赖。
结论先行：**用户侧没有密码登录**。身份默认是**匿名设备会话**（HttpOnly Cookie），可选接入**微信网页授权（OAuth 2.0）**换取 openid/昵称/头像；微信不提供好友列表。必须申请的外部凭证只有地图 Key；第三方平台内容仍需官方授权。

## 二、逐项无认证替代

### 1. 用户体系（匿名设备 / 微信 OAuth）

- **现状**：
  - 默认：前端生成 `deviceId`，`POST /api/auth/device` 换取 HttpOnly 会话；不需要手机号、密码；
  - 可选：`/auth/wechat` 走 `snsapi_userinfo`，读取 openid、unionid（有则读）、昵称、头像、城市；**不读取好友列表、手机号、聊天记录**。
- **无认证替代**：不登录也能用全部本机功能；饭搭子/邀请在未登录时以匿名设备身份工作。
- **功能等价性**：单机打卡/筛选/抽店 100% 等价；跨设备同步需要微信登录或迁移 `deviceId`。
- **限制**：微信授权需认证服务号、网页授权域名与备案；匿名身份换设备/清缓存会丢。
- **风险**：会话 Cookie 被窃取可冒充；已用 HttpOnly、SameSite=Lax、HTTPS 下 Secure、30 天过期缓解。
- **结论**：匿名设备满足基础可用；微信登录只解决“我是谁”，不解决“我的好友是谁”。

### 2. 高德 Web 服务 Key（真实 POI / 路线 / 地理编码）

- **替代 A（已实现）**：演示数据源 `provider_demo.py` —— 16 家门店 + 路线生成 + 游玩点位，坐标与几何规则真实，商家事实为示例。
- **替代 B（已实现）**：OpenStreetMap Overpass（无需 Key，ODbL）—— 真实公开 POI，但无评分、人均、图片，覆盖度不均。
- **替代 C（已实现）**：服务端本地计算 —— `haversine` 算距离、`duration_minutes` 估算步行/骑行/驾车时长、`rank_play_spots` 算顺路度。
- **适用范围**：开发联调、演示、无 Key 的个人部署；OSM 适合只关心"有什么店、在哪"的场景。
- **功能等价性**：
  - 名称 / 地址 / 坐标 / 距离：等价（OSM 亦可）；
  - 评分 / 人均 / 营业时间 / 门店图：**不等价**（演示源为示例数据，OSM 无此字段）；
  - 路径规划：**不等价**，替代方案为直线距离 × 路网系数，无真实路网与实时路况。
- **限制**：演示数据不能用于真实推荐；OSM 在国内餐饮覆盖稀疏；本地估算时长误差可达 20–40%。
- **风险**：把示例数据误当真实商家对外展示，会造成误导（已在界面底部与详情页标注"演示数据"）。
- **结论**：不认证可以"跑通功能"，不能"提供真实商业数据"。

### 3. 高德 / 百度 JS API Key（内嵌地图）

- **替代（已实现，且为默认）**：自绘 SVG 简版地图（`static/js/map.js`）。
  - 墨卡托近似投影 + 等距换算；
  - 米色街区底图、暖橘路线、特色街巷加粗光带；
  - 餐饮点（橙底餐叉）、我的位置（薄荷绿脉冲点）、游玩点（薄荷绿圆点）与白色标签；
  - 支持缩放（1.0–1.8 倍）与按点位自适应取景。
- **适用范围**：路线展示、点位关系表达、视觉稿还原。
- **功能等价性**：几何关系、标记语义、路线形态等价；**瓦片底图、实时路况、卫星图、POI 点击详情不等价**。
- **限制**：没有真实道路名称与建筑轮廓；缩放为整体缩放而非瓦片加载；无交通事件。
- **风险**：用户可能误以为是真实地图；已通过"内嵌简易导航"文案与站内说明降低误解。
- **结论**：展示型地图可以完全去 Key；需要真实底图时必须申请（JS Key 本身是公开的，安全性依赖域名白名单）。

### 4. 百度 AK（备源）

- **替代**：高德 → OSM → 演示源的容错链；百度仅作为可选备源。
- **等价性**：字段结构已统一为同一 POI schema，切换对前端透明。
- **限制**：BD-09 与 GCJ-02 存在约 50–500m 偏移，已在适配器内转换；未配置时该源直接跳过。
- **结论**：非必需。

### 5. Flask `SECRET_KEY`

- **现状**：已配置但项目不使用 session、cookie、CSRF token。
- **替代**：无需替代；可保留默认值用于开发，生产可随机生成。
- **风险**：若未来引入 session，弱密钥可导致会话伪造；当前无攻击面。

### 6. 商家图片

- **现状**：直接渲染 POI 返回的 `https://` 图片 URL；无鉴权、无代理、无下载。
- **替代**：图片来源不可用时回落到本地菜系占位图（`static/img/*`）。
- **限制**：部分平台图片有防盗链或有效期，可能 403/过期。
- **风险**：热链可能违反图片提供方条款；生产建议使用地图官方 SDK 的图片组件或申请授权。
- **结论**：无需认证，但需遵守来源方条款。

### 7. 小红书 / 美团 / 大众点评 / 抖音

- **现状**：**未实现任何抓取**（无 Cookie 池、无签名逆向、无验证码识别、无账号池）。
- **为什么不能"无认证实现"**：
  1. 这些平台的内容接口普遍要求登录态与签名，绕过属于规避技术措施；
  2. 平台协议禁止未授权抓取与再利用；
  3. 评论含个人信息，抓取展示涉及《个人信息保护法》；
  4. 内容受著作权保护，批量复制存在侵权风险。
- **合规替代**：
  - 跳转官方页（已实现：详情页「去高德/百度看完整评价」）；
  - 地图 POI 公开评价摘要（已实现）；
  - 用户手动粘贴链接，本地只存链接与标题、不抓正文（可扩展）；
  - 走官方开放平台 / 商务授权后调用官方 API（需资质与 OAuth）。
- **等价性**：内容丰富度**不等价**；"能看评价/能跳转原平台"部分等价。
- **结论**：这类功能**无法在不认证、不授权的前提下合规实现**；折中方案是跳转与摘要。

## 三、无法在无认证前提下实现的功能

| 功能 | 原因 | 折中方案 | 影响 |
|---|---|---|---|
| 真实评分/人均/营业时间/门店图 | 需地图开放平台 Key | 演示数据（标注）/ OSM（无这些字段） | 真实推荐质量下降 |
| 真实路径规划与实时路况 | 需路径规划 Key | 直线距离 × 路网系数估算 | 时长误差 20–40% |
| 平台笔记 / 短评原文 | 需登录 + 授权，且抓取违规 | 地图摘要 + 官方跳转 | 内容量显著减少 |
| 团购 / 排队 / 预订 | 需商家与平台授权 | 仅跳转，不做交易 | 无法闭环交易 |
| 跨设备同步 / 多端一致 | 匿名设备无法跨端；微信登录需要公众号资质 | JSON 导出/导入；或接微信 OAuth | 手动迁移 / 需资质 |
| 云端数据恢复 | 需账号 + 服务端存储 | SQLite 备份 + 微信登录 | 匿名身份丢失即丢失 |

## 四、风险与建议

1. **不要把"无认证"当成"无限制"**：去掉 Key 只解决技术门槛，不改变数据来源的授权与合规要求。
2. **演示数据必须可识别**：界面上已有「演示数据」标识与「采集说明」入口，避免用户误信。
3. **Key 放在服务端**：`AMAP_WEB_KEY` 只出现在后端环境变量；前端仅使用 `AMAP_JS_KEY`（本身公开，靠域名白名单约束）。
4. **上线前**：配置 HTTPS（定位 API 要求安全上下文）、关闭 Flask debug、设置 `ALLOW_DEMO_FALLBACK=0` 以免线上误用示例数据。
5. **若必须接入平台内容**：走官方开放平台授权，把 OAuth / appkey 作为可配置项接入 `provider_*.py`，不要实现登录态抓取。
