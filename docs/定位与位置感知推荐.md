# 定位与位置感知推荐

> 对应「今天吃啥」定位详情能力：真实定位 → 街道/POI 级地址 → 地图呈现 → 位置感知推荐。

---

## 一、整体功能结构

```
┌──────────────────────────────────────────────────────────────────┐
│ ① 定位采集层  static/js/location.js                              │
│   getCurrentPosition(WGS-84) → wgs84ToGcj02 转换 → 精度/来源元数据 │
│   失败兜底：IP 定位（城市级）→ 手动搜索                           │
└───────────────────────────┬──────────────────────────────────────┘
                            ↓ lat/lng（GCJ-02）
┌──────────────────────────────────────────────────────────────────┐
│ ② 地址解析层  GET /api/locate-context                            │
│   regeo（extensions=all）→ 街道 + AOI/POI 名称                    │
│   landmarks（place/around）→ 地铁/公交/商场/公园/景点             │
│   _area_insight → 区域类型（商圈型/交通枢纽型/休闲型/生活区）      │
└───────────────────────────┬──────────────────────────────────────┘
                            ↓ 结构化 JSON
┌──────────────────────────────────────────────────────────────────┐
│ ③ 地图呈现层  static/js/map.js  MapView.renderLocate             │
│   有 JS API Key → 高德地图：我的位置呼吸点 + 地标标记 + 缩放拖动   │
│   无 Key/加载失败 → SVG：投影 + 虚线连线 + 缩放/拖动/点击          │
└───────────────────────────┬──────────────────────────────────────┘
                            ↓ 地标点击 / 推荐点击
┌──────────────────────────────────────────────────────────────────┐
│ ④ 推荐决策层  services/ranker.py  contextual_rank                │
│   步行可达 40% · 地标邻近 20% · 口碑 20% · 时段匹配 20%           │
└──────────────────────────────────────────────────────────────────┘
```

## 二、数据流转关系

| 步骤 | 位置 | 输入 → 输出 |
|---|---|---|
| 1 | `location.js` `locate()` | 浏览器 `getCurrentPosition` → WGS-84 经纬度 + accuracy |
| 2 | `location.js` `wgs84ToGcj02()` | WGS-84 → GCJ-02（高德/腾讯等国内地图统一坐标系），消除约 500m 偏移 |
| 3 | `location.js` `applyLocation()` | 写入 `App.state.location`（lat/lng/label/accuracy/source/rawLat/rawLng）并持久化 |
| 4 | `locdetail.js` `open()` → `load()` | `API.locateContext(lat, lng, 3000)` |
| 5 | `routes_legacy.py` `/api/locate-context` | 参数校验（坐标范围、半径 1~8km）→ 调 `DataService.locate_context` |
| 6 | `provider_amap.regeo()` | `/v3/geocode/regeo?extensions=all` → 行政区 + `aois[0]`/`pois[0]` |
| 7 | `provider_amap.landmarks()` | `/v3/place/around`（150500\|150700\|060100\|110000\|110200）→ 地标列表 |
| 8 | `data_service._area_insight()` | 地标类型计数 → 区域类型 + 一句话建议 |
| 9 | `data_service.search()` + `ranker.contextual_rank()` | 周边店 → 上下文打分 → 前 8 家带拆解 |
| 10 | `locdetail.js` `render*()` | 渲染坐标卡 / 地址卡 / 地标列表 / 推荐列表 |
| 11 | `map.js` `renderLocate()` | 我的位置 + 地标标记 + 交互绑定 |

**降级链**：GPS 失败 → IP 定位（城市级）→ 手动搜索；高德 JS API 失败 → SVG 交互版；地标接口失败 → 空列表但不阻断定位。

## 三、界面呈现方式

定位详情为全屏浮层（`#locLayer`，`z-index: 96`，从底部滑入），自上而下四段：

| 区块 | 内容 | 交互 |
|---|---|---|
| **坐标卡** | 经度 / 纬度（6 位小数，等宽数字）、精度（如「精度约 25 米」）、来源（浏览器 GPS / IP / 手动搜索）、原始 WGS-84 | 纯展示 |
| **地址卡** | 主行 = POI 级地址（如「北京市朝阳区望京街道 · 合生·麒麟社」）；次行 = 完整地址；标签 = POI 级 / 类型码 / 街道 | 纯展示 |
| **地图** | 我的位置（呼吸绿点）+ 周边地标（字母徽标 + 名称） | 双指/按钮缩放、拖动平移、点标记弹详情 |
| **周边地标** | 类型徽标 + 名称 + 地址 + 距离，按距离升序 | 点击 → 弹层（距离/地址/类型/坐标） |
| **位置感知推荐** | 区域类型徽标、一句话洞察、权重说明、Top 8 店（分数 + 步行分钟 + 最近地标） | 点击 → 进入店铺详情 |

**入口**：首页左上角位置按钮 → 定位弹层 →「查看定位详情」；未定位时点击会引导先定位。

## 四、推荐算法优化方案

### 4.1 问题

原排序只用「直线距离 + 口味偏好」：距离是几何距离，不代表「走多久」；也不知道店铺是否靠近地铁/商场，更不区分午餐与晚餐场景。

### 4.2 打分公式

```
score = 100 × (0.40 × reach + 0.20 × landmark + 0.20 × quality + 0.20 × timeFit)
```

| 分项 | 计算 | 设计意图 |
|---|---|---|
| **reach 步行可达** | `clamp01(1 − (walkMin − 8) / 30)`，`walkMin = distance / 78` | 8 分钟内满分，38 分钟归零；把「距离」翻译成用户真正感知的「走多久」 |
| **landmark 地标邻近** | 取店内最近地标距离 `d`，`clamp01(1 − (d − 300) / 900)` | 300m 内满分、1.2km 归零；靠近地铁/商场意味着交通便利、饭后可顺路延伸 |
| **quality 口碑** | `clamp01((rating − 3.0) / 2.0)`，无评分取 0.5 | 3.0→0、5.0→1；无评分给中性分，避免误伤 |
| **timeFit 时段** | 午餐(11–14)：`1 − |人均 − 50| / 100`；晚餐(17–21)：`0.5 + 0.5 × quality`；其他：0.5 | 午餐偏快偏实惠，晚餐偏正餐偏口碑 |

### 4.3 位置与 POI 信息的三种用法

1. **可达性替代距离**：用步行时间而非直线距离，避免「直线 200m 但隔条河」的误判。
2. **地标作为便利性代理**：地标密度高的区域，餐饮可达性与延伸消费更强；`nearestLandmark` 直接展示在推荐理由里。
3. **区域类型调节解释**：`_area_insight` 依据地标构成判定「商圈型 / 交通枢纽型 / 休闲型 / 生活区」，用于向用户解释「为什么这样排」。

### 4.4 可解释性

每家店返回 `contextScore` 与 `contextBreakdown`（walk/landmark/quality/timeFit 四项 0~1 分值），界面展示分数与「步行 N 分钟 · 近XX」理由，推荐不再是黑盒。

### 4.5 实测样例（望京，21 点）

| 店名 | 分数 | walk | landmark | quality | timeFit |
|---|---|---|---|---|---|
| 芈重山老火锅 | 97 | 1.00 | 1.00 | 0.90 | 0.95 |
| 绥兴盛 | 96 | 1.00 | 1.00 | 0.85 | 0.93 |

区域判定：周边 12 个地标中商场 ≥2 → 「商圈型」；提示「商场集中，餐饮选择多，适合逛吃」。

## 五、接口与文件

| 类型 | 文件 | 说明 |
|---|---|---|
| 接口 | `GET /api/locate-context?lat&lng&radius` | 地址 + 地标 + 洞察 + 推荐 |
| 接口 | `GET /api/regeo?lat&lng` | 单点逆地理（POI 级） |
| 接口 | `GET /api/landmarks`（内部复用） | 周边地标 |
| 后端 | `services/provider_amap.py` | `regeo` / `landmarks` |
| 后端 | `services/data_service.py` | `locate_context` / `_area_insight` |
| 后端 | `services/ranker.py` | `contextual_rank` |
| 前端 | `static/js/locdetail.js` | 浮层编排 |
| 前端 | `static/js/map.js` | `MapView.renderLocate` |
| 前端 | `static/js/location.js` | 定位/坐标转换/兜底 |
| 样式 | `static/css/pages.css` | `.loc-layer` 等 |

**密钥说明**：前端不硬编码任何地图密钥，一律由后端 `bootstrap` 下发 `amapJsKey` / `amapSecurityCode`；未配置或平台不匹配时自动降级 SVG 交互版。
