## 二、模块 A：扩大搜索（半径分页）

### A1 核心问题：只改半径、不翻页，拿到的永远是同一批最近门店

**定位过程**

1. 读 `app.js` 的 `loadMoreByRadius()`：每次取 `RADIUS_STEPS` 的下一档（3→5→8km），请求带 `strict=1`。
2. 读 `data_service.search()`：`strict` 只把 `steps` 限定成单档，仍调用 `provider.search_nearby(lat,lng,radius,keyword)`。
3. 读 `provider_amap.search_nearby()`：固定只取 `page=1,2`，`offset=25`，`sortrule=distance` —— **最多 50 家，且是最近的 50 家**。
4. 真实接口复现（望京 39.9963,116.4703）：

```
radius=3000: count=50 dmin=14m  dmax=221m
radius=5000: count=50 dmin=14m  dmax=225m
radius=8000: count=50 dmin=14m  dmax=346m
3000 ⊆ 5000 : False | 5km 新增 3
5000 ⊆ 8000 : False | 8km 新增 20
```

**问题表现**

- 三档返回的都是同一片 300 米内的店，`dmax` 只有 221~346m；
- 「新增」的 3 条 / 20 条不是更远的店，而是同一批最近结果在不同请求间抖动出来的；
- 用户滑到底看到「附近 8km 内的店都在这了」，但 500 米外的店一家都没出现过。

**根本原因**

分页维度用错了：`radius` 只是查询上界，高德 `/place/around` 按距离排序后只返回 **最近 N 家**。不改 `page` 就永远在同一批里循环，`strict` 只能保证「不越界」，无法让结果「往后走」。

**修复方案**

- 前后端统一改成**按距离升序的游标分页**：`offset` = 已取条数，`limit` = 本次要多少；
- 高德侧按 `page = offset // 25 + 1` 起翻，翻满 `limit` 或遇到空页为止（单次最多 8 页，避免配额被一次请求吃光）；
- 百度用 `page_num`，演示 / OSM 数据源在本地切片；
- 半径退化为「兜底上界」：游标在当前半径翻到底才升档，且**升档保留游标**（数据源按距离排序，不必从头再翻）。

**验证方式与结果**

```
offset=0   count=50 hasMore=True  d=14~221m   dup=0
offset=50  count=50 hasMore=True  d=221~355m  dup=0
offset=100 count=47 hasMore=True  d=358~396m  dup=0
offset=150 count=46 hasMore=True  d=396~478m  dup=1
offset=200 count=0  hasMore=False
唯一门店 192 / 193（1 条为高德页边界重叠，前端按 id 去重）
```

浏览器实测：首屏 50 条 → 触底一次新增 47 条，`offset 50 → 147`，`Feed.items` 距离严格不减。

### A2 `hasMore` 用「满 50 条」推断，提前到底

**现象**：`offset=100` 只返回 47 条（校验/去重掉了几家），后端就回 `hasMore=false`，前端立刻判「到底」，而 `offset=150` 其实还有 46 条。

**根因**：`hasMore = len(items) >= limit` 只是条数启发式，遇到脏数据被过滤就失真。

**修复**：数据源把真实总数写进 `page_info`（高德用响应的 `count`，百度用 `total`，演示/OSM 用切片前长度），后端据此算 `hasMore`；空页强制 `hasMore=false`。

**验证**：`offset=100` 起 `hasMore` 连续为 True，直到 `offset=200` 返回空页才变 False。

### A3 分页越过距离筛选，且「到底」文案写错

**现象**：用户选着「3km 内」，分页却去拉 5km、8km；拉回来的又被前端筛掉，`added=0`，最后提示「附近 8km 内的店都在这了」——和筛选条件矛盾。

**根因**：`loadMoreByRadius` 只按 `RADIUS_STEPS` 递进，没有读取 `Filters.state.distance`。

**修复**：

- 新增 `distanceCeiling()`：选了距离档就以它为硬上限，不再越界；
- 到底文案按真实半径输出，并在未到 8km 时给一个「看看 5km 内的 / 不限距离」按钮，点了直接改筛选并重拉。

**验证**（演示环境）：`radius=3000` 到底 → 出现「看看 5km 内的」→ 点击后 `filterDistance=5000`、`pagination.radius=5000`、状态更新为「附近 5km 内的店都在这了」。

### A4 哨兵常驻可见，连锁升档

**现象**：页面没滑动时也可能连续触发 3km→5km→8km 三次请求。

**根因**：`IntersectionObserver` 的 `rootMargin: 280px` 在短列表下让哨兵一直处于可视区，回调每次渲染后都会再次触发。

**修复**：给列表加 `armed` 标记——只有用户真的滚动过（`pane` 触发 `scroll`）才允许自动加载；短到无法滚动的列表允许自动补一屏，补完再等下一次滑动。每次发起网络加载后 `armed=false`。

**验证**：初始渲染后 `Feed.armed=false`；派发一次 `scroll` 后为 true；`loadMore()` 触网后立即复位。

### A5 追加批次排序规则与首屏不一致

**根因**：首屏 `render()` 走 `personalize()`（按打卡菜系做距离修正），`appendItems()` 只用原始距离排序。

**修复**：追加批次同样过 `personalize()`，保证前后同一套规则；已渲染卡片仍不重排（只追加）。

## 三、模块 B：导航地图

### B1 缩放按钮在高德模式下是「死按钮」

**定位过程**：`nav.js` 的按钮调 `MapView.zoom(el, delta)`；`MapView.render` 在高德分支返回 `{ real:true, zoom: () => {} }`，而 `MapView.zoom` 是模块级 SVG 缩放函数（内部 `querySelector('svg')` 拿不到 SVG 就 return）。

**表现**：有 Key（真实地图）时点「+ / −」毫无反应；无 Key 时正常。

**根因**：高德分支返回的是空实现，且没有把实例暴露给 `MapView.zoom`。

**修复**：引入实例注册表（`WeakMap<el, handle>`），`MapView.zoom(el, d)` / `MapView.reset(el)` 统一走当前实例；高德侧 `map.setZoom()`、SVG 侧 `bindPanZoom`。

**验证**：真实环境 `dataset.zoomLevel` 15 → 16.6（直接调用）→ 18.2 → 19.8（两次按钮）。

### B2 重渲染不销毁旧实例

**根因**：`amapRender` 每次都 `new AMap.Map(el)`，旧实例的 canvas 仍在 DOM 里，返回的 handle 也没有 `destroy`。

**表现**：反复「换一家 / 重新导航」后一个容器里叠了多份地图，内存与事件监听持续增长。

**修复**：`destroyInstance(el)` 在每次 `render` 前销毁旧实例并清空容器；handle 提供 `destroy()`；异步创建加 `mapSeq` 代次校验，快速重渲染时把迟到的实例直接销毁，避免孤儿地图。

**验证**：连点 4 次预算档后 `#playMap .amap-maps` 数量仍为 1。

### B3 容器 0 尺寸导致 center = NaN，`setZoom` 抛异常

**定位过程**：CDP 直接点缩放，页面抛：

```
Invalid Object: LngLat(NaN, NaN)
  at S.setZoom ← Object.zoom (map.js)
```

**根因**：`new AMap.Map` 时若容器尚未布局（页面切换动画 / 隐藏容器），内部 `center` 会退化成 `NaN`；之后任何 `setZoom` 都会在 `getCenter` 上炸。另外 `center` 直接取 `opts.store.lng/lat`，`store` 为空对象时同样得到 `NaN`。

**修复**：

- `safeCenter()` 校验经纬度，非法时回退到默认中心；
- `map.on('complete')` 里补一次 `map.resize()`；
- `setZoom` 包 try/catch，失败退回 `setZoomAndCenter(level, center)`。

**验证**：缩放不再抛异常，`zoomLevel` 正常递增；定位详情地图初始 `15.78`（fitView 后的真实级别）→ 点击后 `17.38`。

## 四、模块 C：饭后游玩地图（吃后逛）

**问题描述**

1. 地图卡片只有一张图，**没有任何缩放 / 复位控件**，也没有「回到店铺」的入口；
2. 每次切换「不限 / 30 分钟 / 1 小时 / 2 小时」都会重建地图（且不销毁）；
3. 地图上的游玩点位不可点击，只能回到下面的卡片点；
4. 底图是纯色块，没有水面、绿地、道路层次，观感不像地图。

**根本原因**

- 模板 `play-map-card` 里只有 `#playMap` 容器，控件从未加过；
- `Play.render()` 直接调 `MapView.render`，既不保存句柄也没有交互绑定；
- `svgMap` 的点位是纯 `<circle>`，没有命中区域与点击回调；
- `blocks()` 只画了矩形街区和两条路。

**修复方案**

| 项 | 改动 |
|---|---|
| 控件 | `play-map-card` 内新增 `+ / − / 回到店铺` 三个按钮，走 `MapView.zoom/reset`，高德与 SVG 都生效 |
| 实例 | `MapView.render` 自带销毁，切档不再叠加（见 B2） |
| 点位 | SVG 点位包成 `.map-spot-hit`，高德 marker 绑定 click，统一回调 `Play.openSpot()`，点击弹详情 |
| 观感 | `blocks()` 增加水面、绿地与树木、主干道描边＋虚线中线；SVG 角落加「示意底图」角标；高德用 `whitesmoke` 样式并加比例尺 / 工具栏 |

**验证**

- 控件数 3，按钮后 `zoomLevel` 15 → 18.2，`reset` 后 SVG `scale(1)`；
- 点击点位弹出「巷口手冲咖啡 / 小众特色 · 咖啡」；
- 4 次切档后容器内只有 1 个 `.amap-maps`。

## 五、模块 D：定位详情地图

**问题描述**：从公开入口 `App.openLocDetail()` 调用时，定位详情浮层不打开（点击无反应）。

**定位过程**：`app.js` 里写的是 `App.openLocDetail = LocDetail.open;`，而 `LocDetail.open()` 内部依赖 `this.layer`、`this.load()`。赋值后调用时 `this` 变成 `App`，`this.layer` 为 `undefined`，函数第一行 `if (!this.layer) return;` 直接退出。页面内的按钮走的是 `LocDetail.open()`（`location.js`），所以平时看不出来，只有通过 `App.openLocDetail` 才会失效。

**修复**：改为闭包调用 `App.openLocDetail = function () { LocDetail.open(); };`

**验证**：CDP 调用后 `#locLayer` 打开、高德地图渲染、缩放 15.78 → 17.38。

## 六、统一的地图层改造（支撑上面四个模块）

`static/js/map.js`：

1. **实例注册表**：`WeakMap<el, handle>`，一个容器同时只有一个地图；
2. **统一句柄**：`{ real, zoom(delta), reset(), destroy() }`，SVG 与高德同签名；
3. **`bindPanZoom`**：SVG 底图统一支持拖拽平移、滚轮缩放、双指捏合、双击放大，并在拖拽后抑制误触点击；
4. **加载占位**：高德异步加载期间显示「地图加载中…」，避免一片空白；
5. **异步代次校验**：快速重渲染时丢弃迟到的地图实例；
6. **缩放级别记账**：`dataset.zoomLevel` 记录当前级别，`getZoom()` 早期返回 undefined 也不会算成 NaN。

## 八、遗留与后续

1. **翻页深度**：高德单点 3km 内总量约 192 家，继续下翻需要更多页；当前单次最多 8 页、总计可翻到 1000 条，超出后升档。若产品需要「无限下拉」，需要考虑按品类拆分查询（火锅/日料/小吃分别翻页）。
2. **地图控件位置**：游玩地图的复位按钮为避让高德 logo 上移了 30px，小屏（<360px）需再核对一次。
3. **缓存**：同一位置的下一页结果尚无缓存，快速滑动会重复请求；后续可在 `data_service` 加短 TTL 的半径+offset 缓存。
