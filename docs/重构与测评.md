本轮目标：在不改变产品行为的前提下，把「能跑」的代码整理成**可维护、可度量、可回归**的工程；所有结论都有测试或实测数据支撑。

> 本轮遗留项（WebP、前端错误上报、Nginx 配置）已在 [测评改进记录](测评改进记录.md) 中完成，本文数据保留重构当轮的对比基线。

## 一、重构范围

| # | 事项 | 之前 | 之后 | 收益 |
|---|---|---|---|---|

| 9 | 资源打包 | 无 | 启动时按依赖顺序拼接，内存缓存 | 无 npm/构建链，仍有单文件收益 |
| 10 | 可观测性 | 仅框架默认日志 | API 访问日志：方法、路径、状态、耗时、requestId | 定位慢接口与 4xx 更快 |

```

services/* ── 数据、社交、持久化

之后：
app.py             app = create_app()，仅保留启动
services/app_factory.py
  ├─ bundles.py          启动时合并 CSS/JS
  ├─ web_security.py     CSP/安全头/同源/限流/gzip/缓存/访问日志
  ├─ routes_pages.py     / 与 /i/<token>、/assets/app.{js,css}
  ├─ routes_legacy.py    /api/bootstrap|restaurants|route|play-spots|…
  └─ api_v1.py           /api/auth|buddies|invites|deals|dice
```

前端：

```
util → store → api → pager → map → bubbles → filters → feed → detail
     → nav → play → checkin → buddy → deals → draw
     → router（页面栈/返回键/导航态） → location（定位/手动商圈）

```

## 四、关键实现说明

### gzip 中间件

- 只压缩文本型 MIME（`text/*`、JSON、JS、SVG），图片跳过；
- 小于 1KB 不压，避免负收益；
- 静态文件默认 `direct_passthrough`，先关闭再读入内存，保证 CSS/JS 也能压缩；
- 设置 `Vary: Accept-Encoding`，避免代理缓存串味。

### 资源打包

- 启动时读入 `JS_ORDER` / `CSS_ORDER`，拼接后计算 `sha1[:12]`；
- 路由 `/assets/app.js`、`/assets/app.css` 返回内存内容，`Cache-Control: immutable`；
- 模板用 `?v=<hash>` 引用，内容变化即换 URL，天然避免旧缓存。

### 错误统一

- `ApiError(code, message, status, hint)` 继承 `FriendlyError(message, hint, code, status)`；
- `FriendlyError` 根据 `code` 映射状态码，未知错误默认 400（此前会返回 200）；
- 处理器只保留一个，响应统一包含 `code / message / hint? / requestId`。

## 五、兼容与风险

| 风险 | 处理 |
|---|---|
| 移除 Bootstrap 导致基础样式变化 | 自有 reset 已覆盖 `box-sizing / margin / 字体继承 / img`；88 项 E2E 与截图对比无差异 |
| 打包后难以定位源码 | 每个片段带 `/* @bundle <file> */` 标记，浏览器可搜索定位 |
| 打包缓存粒度变粗 | 任一 JS 改动都会换 hash；这是静态资源常规取舍 |
| gzip 增加 CPU | 仅文本且 >1KB，level 6；本地 p95 未上升 |
| 限流放宽被滥用 | 仅演示模式放宽搜索限流；真实 Key 下仍按 40 次/分 |
| 生成包在启动时构建 | 20 个文件、约 225KB，启动耗时 <50ms |

**回滚方式**：模板改回按文件引用即可绕过打包；`web_security.py` 删除 gzip 钩子即可关闭压缩，二者互不依赖。
